# 脅威モデリング（STRIDE、P0）

I-05 の決定により、STRIDE で2回行う。1回目は P0 で全体を見る（この文書）。2回目は P2 で、Google の OAuth とカレンダーの同期を入れる前に行う。

- 実施日：2026-11-23
- 対象：コンテナ図（[c4.md](c4.md)）の範囲。P1〜P3 の機能を含める
- 状態：「対策済み」はリポジトリに入っているもの、「設計済み」は要件・決定はあるが未実装のもの、「未決」は Issue（ラベル `decision`）で決めるもの

## 守るもの

| 資産 | 理由 |
|---|---|
| 外部のトークン（Google、Slack の OAuth） | 漏れると、利用者の予定やワークスペースを読み書きされる |
| 利用者の認証情報（パスワードのハッシュ、リフレッシュトークン、個人用トークン） | なりすましの入口 |
| マップ・タスク・予定の内容 | 個人の考えや予定が含まれる |
| 秘密情報（署名鍵、暗号化の鍵、DBのパスワード） | 漏れると上の全部を失う |
| 利用者の外部のカレンダー | AIや同期の誤りで、予定を壊したり作りすぎたりする |

## 信頼の境界

1. ブラウザ・MCPクライアント ↔ API（インターネット越し。P4 以降は公開）
2. API・ワーカー ↔ 外部のサービス（Google、Slack、Webプッシュ）
3. API・ワーカー ↔ LLM（入力に外部由来のテキストが混ざる）
4. アプリ ↔ PostgreSQL（ワークスペースの境界は RLS で守る）
5. 開発者・AIのエージェント ↔ リポジトリ（公開リポジトリ）

## 脅威と対策

| # | 分類 | 脅威 | 対策 | 状態 |
|---|---|---|---|---|
| S-1 | なりすまし（Spoofing） | パスワードの総当たり・使い回しでログインされる | Argon2id（NF-05）、アカウントとIPの組での試行制限と段階的な待ち（AU-08、C-20）、登録の許可リスト（AU-11、C-18） | 設計済み |
| S-2 | なりすまし | 盗んだアクセストークン・リフレッシュトークンで使われる | アクセストークンは15分（NF-06）、リフレッシュトークンはローテーションし、再利用を検知したら系列ごと失効（C-21）、Cookie は HttpOnly・Secure・SameSite=Strict（C-19） | 設計済み |
| S-3 | なりすまし | MCPの個人用トークンが漏れる | トークンはハッシュで保存し、一覧と失効の画面（SC-18）、権限を読み取りとノードの追加に絞る（E-05） | 未決（E-05） |
| S-4 | なりすまし | OAuth のコールバックを偽装され、他人のアカウントを連携させられる | 認可コード＋PKCE、`state` の検証（06-integrations） | 設計済み（P2で再確認） |
| T-1 | 改ざん（Tampering） | 他人のワークスペースのマップやタスクを書き換える | RLS（D-14）と、テーブルの所有者ではない専用ロール。所属はトランザクションごとに設定（D-19）。結合テストで別ワークスペースが見えないことを確かめる（I-01） | 対策済み（土台）、機能ごとに設計済み |
| T-2 | 改ざん | 操作APIに不正な操作（循環、ルートの削除、巨大なバッチ）を送る | サーバーで検証して 409・422、1バッチ1,000件、1,000字、2,000トピックの上限（`.kiro/specs/map`） | 設計済み |
| T-3 | 改ざん | 画面とワーカーの更新がぶつかり、作業枠の状態が壊れる | `version` の楽観ロック（C-09） | 設計済み |
| T-4 | 改ざん | 依存ライブラリ・Actions のすり替え（サプライチェーン） | Actions はコミットのSHAで固定、Dependabot、pip-audit・npm audit・Trivy（NF-10、ADR 0034） | 対策済み |
| R-1 | 否認（Repudiation） | 誰がマップを変えたか分からない | 操作ログに actor と origin（user・ai・import・restore）を残す（D-15） | 設計済み |
| R-2 | 否認 | 管理者の操作（停止、許可リストの変更）の記録が無い | 管理用のコマンドの操作を監査ログに残す（C-27） | 設計済み |
| I-1 | 情報漏えい（Information disclosure） | OAuth のトークンがDBから漏れる | アプリの鍵で暗号化して保存し、AWSでは KMS（NF-07） | 設計済み |
| I-2 | 情報漏えい | 秘密情報をコミットしてしまう（公開リポジトリ） | `.env` は管理外、pre-commit と CI の gitleaks、Claude Code に `.env` を読ませない（ADR 0018） | 対策済み |
| I-3 | 情報漏えい | 存在しないマップと見る権限の無いマップを区別され、IDの存在を知られる | どちらも同じ 404（実装規約、`.kiro/specs/map`） | 設計済み |
| I-4 | 情報漏えい | 予定の本文やマップの内容がログやLLMに渡る | ログに本文を残さない。LLMに渡す範囲を決める（E-04） | 未決（E-04） |
| I-5 | 情報漏えい | XSS で画面のトークンや内容を盗まれる | React のエスケープ、Markdown の描画はサニタイズ（MM-15、PX）、CSP を設定する | 設計済み（CSP は P1 で設定） |
| D-1 | サービス拒否（Denial of service） | ログインやAI提案のAPIを連打される | 試行制限（C-20）、AIの呼び出しは利用者ごとに同時実行数と回数を制限する | 一部未決（AIの上限は P1 で決める） |
| D-2 | サービス拒否 | 巨大なマップや操作でAPIとブラウザが重くなる | 上限（2,000トピック、1,000字、1バッチ1,000件） | 設計済み |
| D-3 | サービス拒否 | 外部APIの429・障害で同期が止まり、ジョブが溜まる | バックオフ、再試行の上限、job_runs の記録、ジョブの状態の画面（SC-19） | 設計済み |
| E-1 | 権限昇格（Elevation of privilege） | プロンプトインジェクションで、AIに予定を作らせたり、データを読ませたりする | 外部由来のテキストはデータとして扱う（NF-11）。LLMが書き込めるのは提案だけで、確定は利用者の承認（ADR 0006） | 設計済み |
| E-2 | 権限昇格 | アプリのDBロールで RLS を回避する | `thinkronos_app` は NOBYPASSRLS で所有者ではない。マイグレーションは別のロール（ADR 0035） | 対策済み |
| E-3 | 権限昇格 | AIのエージェント（Claude Code）が `main` を変えたり、PRを勝手にマージしたりする | フックと設定の禁止リストで止める。ルールセットは管理者も例外にしない（ADR 0013） | 対策済み |

## 残る課題

- S-3（E-05）、I-4（E-04）、D-1 の AI の上限は、それぞれの決定の Issue で決める。
- CSP の内容は、フロントの画面を作る最初のPR（実装計画 1-4）で決める。
- 2回目（P2）は、Google の OAuth、トークンの暗号化と更新、同期、連携の解除（D-10）を中心に見直す。
