# ツールの使い方の記録

AIツールごとに、機能・使ったクレジット・手戻り・気づきを残す。新しい記録は各ツールの節の先頭に足す。

## Claude Code

### 2026-11-23：Issue #13「バックエンドの土台を作る」
- **使った機能**：`/issue-workflow`（計画 → 承認 → 実装 → PR → 結果）、`web-fetch` エージェントで公式の文書と PyPI の確認、Testcontainers・compose を使った動作確認。
- **使ったクレジット**：未計測。
- **手戻り**：
  - フックが cwd からの相対パスで書かれていて、`backend/` に `cd` した後の Bash がすべて止まった。`$CLAUDE_PROJECT_DIR` 起点に直した。
  - `alembic.ini` と `.importlinter` を、Windows の既定の文字コード（cp932）で読まれて失敗した。`alembic.ini` は ASCII にし、import-linter は `PYTHONUTF8=1` で実行する。
  - Celery の `@app.task` は既定で全アプリに共有され、テストで2つ目のアプリのタスクが無視された（`shared=False`）。
  - Celery が標準出力を横取りし、1行1JSONのログに接頭辞が付いた（`worker_redirect_stdouts=False`）。
  - 手元の DB のボリュームの所有者のパスワードが `.env` と違っていた（stub は DB につながないので気づかなかった）。確認は別の compose プロジェクト（`-p thinkronos-check`）で行った。
- **気づき**：
  - Strands の Ollama の文書のページが 404 だった。引数はインストールしたパッケージのソースで確かめた。
  - 自動モードの分類器は、Issue の指示にあっても `.claude/settings.json` の deny の変更を止める。人の作業として残す。
  - Windows の Docker Desktop で、Testcontainers の Ryuk のポートの割り当てが間に合わず、結合テストがときどき失敗した（再実行で通る）。

### 2026-11-23：Issue #12「AIツールの規約とエージェントの型を整える」
- **使った機能**：Issueの指示コメントを読んで計画を投稿（`gh`）、公式ドキュメントの確認をサブエージェントに委任、フック、サブエージェント、スキル、ヒアドキュメントでのファイル作成。
- **使ったクレジット**：未計測（この環境では使用量を確認できなかった）。
- **進め方**：計画をIssueにコメントして止まる → 「## 承認」を読む → 実装 → PR → 「## 結果」。承認の補足（uv経由のフック、developも止める）が計画より優先された。
- **手戻り**：
  - ブランチ保護フックの判定が、複数行のコマンド文字列の中の別の行まで拾い、無関係なコマンドを止めた。判定を同じ行に限った。コマンド文字列の一致を見る方式なので、文章中に `git push … develop` と書くだけでも止まることがある（その行を分けて書けば通る）。
  - フックの標準エラー出力がWindowsの既定の文字コードで化けた。UTF-8に切り替えた。
  - Git Bash の `/tmp` のパスを Windows の Python に渡すと開けない。テストでは `cygpath -m` で変換した。
- **気づき**：
  - このPCには Python の実体がなく、フックは `uv run --no-project python …` で動かす。
  - `.claude/agents/` と `.claude/skills/` は、セッションの開始時に読まれる。作ったセッションでは呼べない（`Agent type '…' not found`）。確認は新しいセッションで行う。
  - サブエージェントの報告は「指示のように見える文」を含むことがあるので、内容は参考として扱い、権限や設定の変更は自分の判断で行う。
  - 自動モードの分類器は、権限の設定ファイルの書き換えと、`.env` 系の読み取りを止める。

### 試した結果（エージェント・スキル）
`.claude/agents/` のエージェントは、作成したセッションでは呼べなかった。代わりに、定義ファイルの本文を指示にした汎用エージェントで、中身の動作を1回ずつ確かめた。**登録されて呼べるかは未確認（新しいセッションで確認する）。**

| 対象 | 試した方法 | 結果 |
|---|---|---|
| design-reviewer | 汎用エージェントで `git diff develop...HEAD` を対象に実行 | 差分が設定と文書だけなので、ポート・RLS・認可は「対象なし」と返った。補足の指摘：deny の `Read(./.env.*)` が `.env.example` も塞ぐ。`Bash(make *)` は広い許可。フックのブランチ判定は `cwd` 依存。定義の不足：重大度の基準、差分が設定だけのときの扱い、ADRを全文読むか、`Bash` の範囲 |
| docs-consistency-checker | 汎用エージェントでリポジトリ全体を対象に実行 | ずれを9件、ずれなしの確認項目を多数返した（主なもの：ADR 0006・0013・0015 の未作成への参照、`docs/adr/README.md` の「このPR」という書き方、ADR 0034 内の記述の矛盾、`ollama/ollama:latest` の版が固定されていない）。定義の不足：前方参照を「ずれ」に数えるか、重大度、既存ADRへの追記の扱い |
| test-writer | 汎用エージェントで `block_protected_branch.py` を対象に、ファイルを作らずケース案だけ出した | テスト計画が無いので手順1で止まるべきところ、暫定案（約20ケース）を出した。定義の不足：計画が無いときは止まって報告だけにする、テストの配置・フレームワークの流儀 |
| issue-workflow | スキルとしては未実行。この作業そのものが同じ手順（計画 → 承認 → 実装 → PR → 結果）で進んだ | 手順の文面は実作業で破綻しなかった。スキルとしての呼び出しは未確認 |
| write-adr、split-tasks-to-issues | 未実行 | 対象のADR・tasks.md が今は無い。次のセッションで、それぞれ呼べることだけ確認する |
| create-migration、add-e2e-scenario | 未実行（ひな形） | コードが入ってから埋める |

### 動作を確かめたもの（フック）
- `block_protected_branch.py`：一時リポジトリで、`main` と `develop` 上の `git commit`／`push`／`merge` は終了コード2、`feature/x` 上は0、`git status` は0、feature 上の `git push origin develop` は2。
- `format_on_save.py`：末尾空白の除去、CRLFからLFへ、末尾の改行1つ。Markdown の行末スペース2つは残る。
- どちらも `uv run --no-project python` 経由で実行した。Claude Code から呼ばれる経路では、`develop` 上の実コミットがブロックされることは確かめていない（作業ブランチ上だったため）。

## Kiro

- 2026-11-23 導入。Kiro IDE（Free プラン、モデルは Auto、権限は Accept file changes）。データ共有は Usage Analytics と Content Collection の両方をオプトアウトした。

### マップの仕様（Issue #15、2026-11-23）

| 段階 | 使ったクレジット（累計） | 手戻り |
|---|---|---|
| design.md（Design-First） | 約15（15） | 楽観的更新が無い、sort_key の衝突、403、d3-zoom など10点を指示で直させた |
| design.md の修正、requirements.md、Analyze Requirements | 約20（35） | 分析の質問は6件。2件（seq の同値、5xx の扱い）は前提の誤り |
| tasks.md | 約5（39.5） | 層ごとの分割で、PRごとに動くものが無かった。機能ごとの縦の分割に手で組み直した |

気づき：

- 仕様1つで Free の月50クレジットの約8割を使う。P1 で Kiro の仕様をもう1つ作るなら Pro が要る。
- リポジトリの既存の実装（RLS の関数、UoW）を読まずに「作る」と書くことがある。入力に既存のファイルを明示する。
- 指摘が多い修正は、Kiro に頼まず手で直すほうがクレジットを使わない。Kiro には次の段階の生成だけを頼む。
- Analyze Requirements の質問には、前提を取り違えた選択肢が混ざる。選ばずに自由入力で前提を正すことがある。
- tasks.md の `*`（任意のテスト）は、テストを必須とする規約に合わないので外した。
