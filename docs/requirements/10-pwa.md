# PWA対応

PWAは「インストールできる」「オフラインで直近のデータを閲覧できる」「Web Pushで通知できる」の3点に絞り、P3で対応する。オフラインでの編集は、同期の競合解決が必要になるため扱わない。

## 実装方針

- vite-plugin-pwa（Workbox）で、Webアプリマニフェストと Service Workerを生成する。
- アイコン、テーマカラー、起動画面を用意し、PCとスマートフォンのホーム画面にインストールできるようにする。
- 新しいバージョンのService Workerを検知したら「更新があります」と表示し、利用者の操作で切り替える。
- ログアウト時は、キャッシュとIndexedDBのデータを消す。

## キャッシュ戦略

| 対象 | 戦略 | 理由 |
| --- | --- | --- |
| アプリの外枠（HTML、JS、CSS、アイコン） | 事前キャッシュ | 起動を速くし、オフラインでも画面を開けるようにする |
| 読み取り系のAPI（マップ、予定、タスク） | Network First（失敗したらキャッシュを返す） | 通常は最新を優先し、オフライン時だけ直近のデータを出す |
| 認証と書き込み系のAPI | キャッシュしない | 古い状態を見せたり、操作を取りこぼしたりしないため |
| オフライン閲覧用のデータ | 直近に開いたマップと、今日・明日の予定をIndexedDBに保存する | オフラインでは閲覧専用にする |

## Web Push通知

- VAPIDの鍵を発行し、ブラウザの購読情報をサーバーの `push_subscriptions` テーブル（user\_id、endpoint、鍵、作成日時）に保存する。
- 通知の内容は、作業枠の開始前のお知らせと、朝のブリーフィング。Slackと Web Pushのどちらで受け取るかは、ユーザー設定で選べるようにする。
- iPhoneでは、ホーム画面に追加したPWAでのみWeb Pushを受け取れる（iOS 16.4以降）。

## ローカルでの確認

- Service Workerは安全な接続（HTTPS）でしか動かないが、localhostは例外として動く。PCでの開発はそのまま確認できる。
- スマートフォンの実機で確認するときはHTTPSが必要なので、mkcertなどでローカル用の証明書を作る。
- マニフェストとService Workerの状態は、Chromeの開発者ツールのApplicationパネルで確認する。
