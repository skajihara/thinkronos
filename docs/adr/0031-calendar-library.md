# 0031 カレンダーのライブラリ

## 状態

承認済み、2026-11-23

## 背景

カレンダーのライブラリを決める必要があった（B-06）。マップのノードをカレンダーの時間枠へドラッグして作業枠を作れること（CL-09、R-13）、終日予定と祝日の表示（D-20、CL-06）、キーボード操作とアクセシビリティ（B-07）が条件。マップのノードのドラッグは、ADR 0012に従い自前のPointer Eventsで実装している。

## 比べた選択肢

1. **FullCalendar 7.1.5**（MIT）：外部からのドロップ用に `ThirdPartyDraggable` がある。
2. **react-big-calendar 1.20.0**（MIT）：外部からのドロップはHTML5 DnDが前提で、方式が異なる。

除外：Toast UI Calendar（`@toast-ui/calendar` 2.1.3、最終リリース2022-08-16で更新停止）。Schedule-X（MIT、`@schedule-x/calendar` 4.9.1、2026-09-29）は計画の段階で「有料／保守停滞」として外したが、npmでは保守が続いており、**外した根拠は確認できていない**（未検証）。

## 決定

**FullCalendar v7** を採用する。

## 理由

主要な確認結果（出典は `RESULT.md`。Playwrightは `timezoneId: Asia/Tokyo`、両ライブラリで12件すべて通過）：

| 確かめたこと | FullCalendar 7.1.5 | react-big-calendar 1.20.0 |
|---|---|---|
| ノード→時間枠ドロップで60分枠 | ○ 公式機能（`ThirdPartyDraggable` + `eventReceive`） | ○ 自前実装（約50行） |
| ドラッグ中の強調 | ○ ライブラリのプレビュー枠 | ○ 自前オーバーレイ |
| 移動・長さ変更 | ○ 標準 | ○ `withDragAndDrop` |
| 終日予定・祝日 | ○（祝日の列の色付けは未確認） | ○ |
| キーボード/a11y | △ `eventInteractive` でTab到達。矢印等で枠は動かせない | △ 既定でTab到達。矢印等で枠は動かせない |
| 最終リリース | 2026-11-12 | 2026-06-01 |
| gzip増分（JS+CSS） | +89.2 kB | +89.3 kB |

- 決め手：マップの自前ドラッグを `ThirdPartyDraggable` がそのまま受け、日時の判定、15分スナップ、プレビューをライブラリに任せられる。
- react-big-calendarも実現できたが、ポインタ座標から日時への変換とハイライトを約50行で自前実装した。この変換はライブラリのDOM構造（`.rbc-day-slot`）に依存している。
- 差は大きくない。キーボード・a11y、ライセンス、バンドルサイズには差がない。「マップが主役で、ドラッグ元は自前」という構成での保守しやすさが理由。

## 影響

本実装での条件：

- バージョンを固定し、FullCalendarは1つのアダプター部品に閉じ込める。
- キーボードだけで作業枠を作成・移動する操作は、どちらのライブラリにも標準では無い。自前の代替操作を作る（例：ノードを選択して「カレンダーに追加」ダイアログ）（B-07）。
- タッチ操作と祝日の列の色付け（背景イベント）は本実装で確かめる。

注意点・残る課題：

- v7は構成が変わっている（`@fullcalendar/react` 1つにプラグイン、`temporal-polyfill` が必要）。v6と混在しやすい。CSSクラス名がハッシュ化されるため、テストは `data-date`、`data-time`、`role` を手がかりにする。
- 長さ変更時の終了時刻の決め方がライブラリで異なる。FullCalendarは「ポインタがある15分セルの下端」。操作感を本実装で確認する。
- 未確認：スクリーンリーダー実機、タッチ操作、ドラッグ中の自動スクロール（画面外の時間帯へのドロップ）、axe等の自動検査、祝日データの取得元（試作は固定配列。本番は内閣府の祝日CSV等を取り込む案）。
- Schedule-Xは未検証のまま。
