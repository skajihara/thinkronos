# 0006 計算とLLMの役割分担

## 状態

承認済み、2026-11-23（企画書の AI機能設計の原則を記録したもの）

## 背景

自動スケジューリング（AI-07、AI-08）は、空き時間を探し、タスクの期限と優先度から枠を選び、理由を説明する。ローカルのLLM（qwen3:8b、ADR 0032）は、日付の計算や重なりの判定を間違えることがある。予定の重なりや稼働時間の外への配置は、利用者に実害がある（E-03 の合格基準は「重なり0件」）。

## 比べた選択肢

| 案 | 特徴 |
|---|---|
| LLMに全部させる（予定の一覧を渡し、枠を選ばせる） | 実装は少ない。日付・時刻の計算と重なりの判定を誤り、誤りを再現できない |
| コードだけ（決まった規則で詰める） | 確実だが、優先順位の判断や自然文の解釈、理由の説明ができない |
| 計算はコード、判断と説明はLLM | 空き時間と制約はコードで確実に出し、LLMはその中から選んで理由を書く |

## 決定

計算は決定的なコード、判断と説明はLLMにする。

- コード：今の日時（`get_now`）、相対的な日付の解決（「来週」など。E-01）、空き時間の計算（`find_free_slots`）、承認の時点の重なりの再確認。
- LLM：優先順位の判断、自然文の解釈、提案の理由の文章。
- LLMが書き込めるのは `propose_blocks`（作業枠を「提案」として保存する）だけ。確定とGoogleへの書き込みは、利用者の承認のあとに通常のAPIで行う。

## 理由

- 重なりや稼働時間の違反をコードで出さないようにすれば、LLMを替えても（Ollama → Bedrock）安全性が変わらない。
- 空き時間の計算は単体テストと性質ベースのテストで確かめられる。LLMの出力は評価セット（E-03）で確かめる。
- LLMが外部に直接書き込まないので、プロンプトインジェクション（NF-11）で予定が勝手に作られることがない。

## 影響

- `find_free_slots` は domain 層の純粋な関数として作り、稼働時間帯・既存の予定・バッファを入力にする。
- 承認の時点で空き時間を計算し直し、重なっていれば 409 にする（フロー3）。
- LLMが空き時間の外の枠を返したら、サーバーが拒否して捨てる（記録は残す）。
